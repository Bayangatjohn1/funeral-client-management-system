## Tokens already present

`shared_filter_ui.blade.php` defines light filter surface `#D0E2D6`, menu `#F4F8F5`, border `#AEC7B7`, text `#081D13`, focus `#1B4332`; dark equivalents are surface `#14261D`, menu `#112218`, border `#29523D`, text `#F8FAFC`, focus `#34D399`. Shared case rules derive `--shared-filter-*` from these. These are source-confirmed tokens, not proof that a more specific rule does not cover them.

For composite fields, the uniform input rule reads `--filter-control-background` and `--filter-control-border`. Set those to transparent/0 where the wrapper owns the surface, rather than stacking another border over the select. Search and page-size fixes depend on this. Inspect token inheritance and specificity for the target before reusing it.

## Verified aspects and exclusions

- The 2026-11-01 focused suite passed 15 tests / 76 assertions: completion, print access, draft policy, and case toolbar presentation. This verifies those exercised behaviors, not hover colors or phone layouts.
- A native Edge light desktop screenshot showed the case table and three icon actions with usable spacing. Final header, hover, active-chip, and icon-color revisions occurred afterward and remain visually pending. Branch Admin, Staff, Owner, dark, and narrow states are not automatically covered.
- Source inspection confirms Promotions views/routes exist. Their presence is **not** acceptance of the feature or its flows. Treat unfinished/proposed Promotions behavior as planned/unverified; do not advertise it as completed or use it as an authoritative standard.
- No new filters, grid views, status transitions, or schema changes are authorized by this reference. Date completion and scheduler deployment are outside presentation adoption; see the separate operational review if asked.
