## Results and forms

Each directory has cards and table results plus **one** common footer node. Branch/User use a25-record page limit and hide that footer when the filtered paginator has only one page; it appears only when the matching result set exceeds25 records (or a later page is active). Keep the hidden node in the async result response so a filter/search can cross the threshold without a full reload. Audit always retains its applicable list footer. A visible footer is a separate sibling after the results/scroller, min64px,12px gap, count left/navigation right. Existing flex ordering must not move it above the toolbar. It is replaced with the new result response but excluded from skeleton/inert regions. Headers/toolbar/sidebar stay usable; view switching masks only the visible result region. Empty results maintain clamp(20rem,40vh,30rem),18rem narrow; original table columns remain in horizontal overflow.

Tables use6px corners, transparent headers13px/600 with .055em tracking, readable14px cells and soft row-outline hover. Actions retain neutral default glyphs, semantic green view/enable, amber edit and red disable on hover/focus, no glow/background/transform. Use shared accessible tooltips above the action with viewport clamping; clicking dismisses, restored focus alone must not reopen the tooltip. Existing business actions and confirmation flows remain.

Forms keep existing sections, entry modes, validation and permissions. Labels14px/500 with8px gap, fields44px/8px,20px field grid gaps and quiet help text. Word-initial capitalization applies only to edited names/addresses, on blur/submit, with matching server normalization for saved values. Uppercase the first Unicode letter of each word while preserving subsequent spelling/acronyms; collapse whitespace at commit, never trim spaces during typing. Email/password/contact/IDs/codes/amounts are excluded. Historical values are not bulk rewritten. Existing catalog capitalization modes are unchanged.

### Branch/User status-action feedback — 2026-11-04

- Branch Disable/Enable retains its preflight blocker check. Show **Checking branch status** while it runs, a specific blocker explanation with counts when applicable, or a confirmation that names the branch. On submit, disable the confirm control, set `aria-busy=true`, and change the copy to **Disabling…** or **Enabling…**. The server success message must identify branch code/name and resulting status; validation errors remain visible on return.
- User Activate/Deactivate must render one permission-scoped confirmation dialog and PATCH form for every visible directory user in both Grid and Table views. The same dialog may be opened from User Information and must return focus correctly. On submit, disable the confirm control, set `aria-busy=true`, and use **Deactivating…** or **Activating…**. Success identifies the user and resulting status; own-account, Owner, cross-branch, and last-System-Admin safeguards remain server-owned.
- User dialogs live inside `[data-record-results-dialogs="users"]` so async search/filter/pagination replaces their record metadata/forms together with the results. The delegated dialog owner is initialized once; replacement HTML strips duplicate scripts and dispatches `record-results:updated` for rebinding. Never leave a status trigger without its matching dialog/form.
