# View rows and eye interaction

Scope: Case Records, Master Case Records, Payment Monitoring, Branch/User Management and Service Management. Existing View URLs, permission-rendered controls, modal loaders, table columns and record content are retained.

Rows containing an enabled View control are initialized with `data-clickable-row` and a keyboard focus stop. The existing eye receives `data-row-view-trigger`. Row clicks and Enter delegate to that same control; links, buttons, menus, inputs and text selection remain independent. The delegated row handler is installed once per document, including after case-result refreshes. Rows without a View control and empty rows are excluded. Cards and transaction expand/collapse controls retain their existing behavior.

Row hover inherits `--record-view-ink` (#1B4332 light / #5CE0A0 dark) only into the eye controls. The eye shape and transparent background remain; its glyph now shrinks subtly on hover as described in the latest revision, with no glow or shadow. Existing table row hover backgrounds remain owned by the original page styles. Local Case, directory and Service rules consume the inherited View color rather than hiding it behind neutral overrides.

Tooltips remain attached to controls, never rows. The shared eye tooltip retains its existing text and positioning; row hover supplies the View color and glyph scale without opening the tooltip. For these eyes, focus without direct pointer hover does not reveal a tooltip, as explicitly requested. Other controls retain their existing tooltip behavior. Payment's native detail-eye tooltip retains its existing positioning mechanism.

Payment's main history row already opened its existing modal but had no separate eye. An eye using the existing primary View design now opens the same modal from the status cell. Its tooltip retains “Open payment history” and row-end positioning; the old tooltip attributes are removed from the row. Click propagation and keyboard target checks prevent parent/child double activation. The existing status-cell responsive placement is preserved.

Owners: `resources/js/app.js`, `resources/js/shared-record-controls.js`, `resources/css/app.css`, `staff/payments/history`, `staff/payments/_consistency_styles`, `partials/case_records_layout_styles`, `partials/services_visual_styles`, `partials/worklist_consistency_styles`, and the Branch view's local neutral-color rule.

Applicability: row activation, eye color and pointer-only eye tooltips apply. Existing routes/loaders are reused. Cards, empty rows and unrelated accordion actions are outside this change. Payment's separate history eye was the only missing corresponding control and is added for the requested consistency.
